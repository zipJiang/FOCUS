Harness

Define the task environment and run the agent through it. Context managers decide what the policy sees, branch points decide where search may continue, and workspaces hold durable task data.

Agent

Section titled “Agent”

Run a policy in a task. Each decision prepares the context, generates an action, applies it to the environment, and records the turn with its exact prompt tokens and behavior log probabilities.

from focus import Agent

agent = Agent(
    policy=policy,
    env=env,
    system_prompt="Solve the task using the available tools.",
    max_steps=32,
)

async with agent:
    root = await agent.start("Your task")
    result = await agent.run(root)

This agent keeps the transcript with AppendOnly and makes every decision boundary available to search. After 32 steps, including compaction steps, it makes one final-answer attempt; set finish_prompt=None to stop without that attempt. Use context=Segments(256) for exact token continuation or context=Summarize(...) for summaries. branch_points selects candidate checkpoints, and execution configures shared capacity and persistence. The agent chooses an action parser from the policy format and the action kind declared by the context manager or environment. Pass parser= to override that choice. Derived agents share the same policy and execution services.

async with agent starts its execution services and closes them on exit, cancelling and awaiting outstanding requests. The caller closes policy clients and checkpoint storage separately. If several agents share services, use one outer lifecycle scope for all their work. Run derived agents inside that scope; use Collector(..., own=False) when a collector borrows it.

Execution

Section titled “Execution”

How an agent’s model calls run, persist, and recover: the shared execution services, an optional checkpointer, retry rules, a resource budget, and a generation timeout.

from focus import Agent, Execution

execution = Execution(retries=3, generate_timeout=120.0)
agent = Agent(
    policy=policy,
    env=env,
    system_prompt="Solve the task.",
    execution=execution,
)

This agent retries a failed generation up to three times and abandons a generation after two minutes. Pass the same Execution to several agents, or to agents built for different policy snapshots, so their requests share one capacity limit. Add a checkpointer to persist rollout states for recovery.

tool

Section titled “tool”

Turn a function into a tool. The tool’s name, description, and argument schema come from the function’s signature and docstring.

from focus import tool

@tool
async def lookup(term: str, limit: int = 5) -> str:
    """Look up a term in the glossary.

    Args:
        term: The word to define.
        limit: How many definitions to return.
    """
    return term

The model sees a lookup tool with a required string term and an optional integer limit. Arguments are validated before the call; a wrong type or unknown argument becomes a ToolError the model can read. Annotate a parameter workspace to receive the branch’s workspace; it is hidden from the model. Return a string or any JSON-serializable value.

Checkpointer

Section titled “Checkpointer”

Define persistence for complete rollout states. Saving records a snapshot; loading returns an isolated state suitable for recovery or branching.

from focus.extend import Checkpointer
from focus.extend import MemoryCheckpointer

checkpointer = MemoryCheckpointer()

Use the in-memory implementation to save and recover isolated states within a process. A custom store implements _put(), _get(), info(), and list(); the base class handles serialization and validation. Pass it through Execution(checkpointer=...). BranchPoints separately selects where search may continue.
