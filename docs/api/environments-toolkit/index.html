Shared tools

This toolkit supplies building blocks for the sample environments rather than a benchmark task of its own. It represents documents as source files and sections, exposes list, grep, and read operations, and provides a Python calculation tool.

What you supply

Section titled “What you supply”

Build a Corpus from your task’s documents and choose the tools to expose through your environment. Configure result lengths, permitted calculation imports, and execution limits to suit the task. The toolkit does not define a question, reward, or completion rule; those belong to your environment.

What to adapt

Section titled “What to adapt”

Reuse the corpus tools when your agent works with read-only evidence. Replace document parsing or tool output formatting when your sources need a different structure. PythonTool runs calculations in a restricted subprocess with resource limits; it is not a container or a security boundary for arbitrary untrusted code.

The reference below covers the document model and individual tools.

Corpus.resolve

Section titled “Corpus.resolve”
def resolve(self, path: str) -> SourceFile | None

A file from what the model typed: an exact path, else a unique suffix.

The suffix has to start at a path-component boundary — a whole tail of the path, never a tail of one name. Bare endswith made "ax.txt" resolve "a/tax.txt" uniquely and confidently, which is worse than not resolving: the model gets a file it did not ask for and cites it.

No basename tier: basename equality implies a boundary-aligned suffix, so it could only ever fire where the suffix pass already found nothing.

Corpus.manifest

Section titled “Corpus.manifest”
def manifest(self, *, label: str='sections') -> str

The file list that goes in the prompt — the discovery affordance.

label is the word this task calls its sections by (“provisions” for a statute, “headings” for a manual): the manifest is prompt text a model reads, so it should use the task’s own vocabulary rather than this module’s.

SourceFile.section_at

Section titled “SourceFile.section_at”
def section_at(self, line: int) -> str

The most specific section containing a 1-based line.

Spans nest, so a line inside (c)(1) is also inside (c). The narrowest one is the citation worth printing: “§63(c)” points at sixty lines, while “§63(c)(1)” points at the rule.
